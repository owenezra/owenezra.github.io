PUBLIC EXPERIMENT · WORKING FORK

Agentic Council

Adversarial review that does not treat the acting model's account as ground truth.

Agentic Council is an open-source multi-model review engine. My public repository is a working fork used to explore evidence access, independent criticism, pre-write review, and the separation of acting and judging roles in tool-using coding workflows.

THE PROBLEM

A model can describe work it did not actually verify.

Tool-using coding agents often produce confident narratives about what they changed, tested, searched, or ruled out.

The narrative is not the evidence.

A model may say that a requirement is outside the task's boundaries, a dependency is unavailable, a test passed, a risk is negligible, or an implementation is complete without having run the probe that would support the claim.

A review system that sees only the acting model's explanation can repeat the same unsupported assumptions.

Agentic Council explores a different pattern: make claims contestable, give critics controlled access to external evidence, and require the actor's proposed changes to pass an independent review boundary.

CORE DESIGN

Separate the actor, the critics, the evidence, and the write authority.

Multiple independent critics

Critics from different model families review the same proposal against an explicit quality bar. Model diversity does not guarantee truth, but it can expose assumptions and failure modes that one model family misses.

Evidence requests

During review, critics can request content from files, allowlisted web sources, or sandboxed commands. The point is not to give every critic unrestricted agency. It is to let the review architecture retrieve concrete evidence without relying entirely on memory or the actor's self-report.

Read-only critics

Critics do not receive general write authority. Their role is to inspect, challenge, and report. This preserves a meaningful separation between proposing a change and deciding whether the proposal is supportable.

Review around state change

The working architecture reviews edits and can place a gate before a proposed write or respond immediately after a write. A tool that can affect state should not be trusted solely because it can also narrate why the change was safe.

Logged verdicts and evidence

Review outputs, requested evidence, concerns, and dispositions are recorded so the process can be inspected and evaluated rather than reduced to an invisible “second opinion.”

WHY THIS MATTERS TO MY WORK

A verification experiment, not an answer to the governance problem.

Agentic Council is relevant to my broader work for three reasons.

First, it treats model output as a set of claims that can be tested against files, commands, and authoritative sources.

Second, it makes the acting-versus-judging distinction explicit. The system that proposes an action should not be the only system that determines whether its own evidence is sufficient.

Third, it creates a record that can support later adjudication and measurement.

Those commitments align with AutoQA Foundation, but AutoQA adds a necessary caution: more critics, more rounds, or stronger consensus do not create missing information and do not automatically confer authority.

WHAT SHOULD BE MEASURED

A review architecture needs an honesty instrument.

The useful question is not “Did the council object?” A high objection rate could mean that the actor is unreliable, the critics over-flag, or the quality bar is poorly specified.

A serious evaluation should measure:

  • concern precision;
  • defect recall on an adjudicated sample;
  • false blocks and false warnings;
  • unique findings contributed by each critic or tier;
  • evidence-request usefulness;
  • coverage and abstention;
  • latency and cost;
  • stability across model and prompt changes;
  • recovery after an incorrect block;
  • whether reviewers catch unsupported claims rather than merely produce plausible prose.

Consensus alone is not a validation method.

BOUNDARIES AND NON-CLAIMS

What this project does not establish.

This project does not establish that:

  • a council of models is more accurate than a well-designed single evaluator;
  • model-family diversity guarantees independent reasoning;
  • majority vote is evidence;
  • a critic with tool access has exhaustively checked a repository or environment;
  • a passed review proves that the code is correct, secure, performant, or aligned with the task's requirements;
  • automatic rollback is appropriate without measured false-block risk;
  • the system should receive consequential authority by default.

It is a working architecture for making review more evidence-oriented and contestable.
